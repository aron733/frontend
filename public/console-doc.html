Documentation API VOKYVO

Console développeur — 30 octobre 2026

L'API VOKYVO vous permet d'intégrer Social et Vokyvo AI dans vos propres applications, bots ou scripts. Toutes les requêtes passent par https://api.vokyvo.com/api/ et sont authentifiées par une clé API personnelle.

1. Créer une clé API

  1. Connectez-vous à la Console développeur.
  2. Cliquez sur + Nouvelle clé.
  3. Choisissez le type : Social (clé vky_...) ou IA (clé vok_...).
  4. Copiez la clé immédiatement (elle ne sera plus affichée en entier).
⚠️ Maximum 5 clés par type. Une clé compromise doit être révoquée immédiatement.

2. Authentification

Toutes les requêtes doivent inclure l'en-tête :

Authorization: Bearer vky_votre_cle_ici

Exemple avec curl :

curl -X POST https://api.vokyvo.com/api/social/publier/ \
  -H "Authorization: Bearer vky_votre_cle_ici" \
  -H "Content-Type: application/json" \
  -d '{"texte": "Bonjour depuis l'API !"}'

3. API Social

Publiez automatiquement sur le fil Social VOKYVO (comme un compte, ou depuis une Page).

POST /api/social/publier/

Champs :

  • texte (string, requis) — contenu du post.
  • page_id (int, optionnel) — publier sous une Page dont vous êtes propriétaire.

Réponse :

{
  "success": true,
  "post": {
    "id": 123,
    "code_court": "aBcD12",
    "url": "https://vokyvo.com/p/aBcD12"
  }
}

4. API IA

Envoyez un message à Vokyvo AI et recevez une réponse textuelle.

POST /api/ia/chat/

Champs :

  • message (string, requis) — la question ou le message.

Réponse :

{
  "success": true,
  "reponse": "Bonjour ! Je suis Vokyvo AI..."
}

5. Rate limits

APILimite / heureLimite / jour
Social (publication)50200
IA (chat)50200

Ces limites sont par compte, toutes clés confondues. Un dépassement renvoie un code 429.

6. Codes d'erreur

CodeSignification
200Succès
400Requête invalide (champ manquant ou mal formé)
401Clé API manquante ou invalide
403Clé révoquée ou compte banni
429Rate limit dépassé
500Erreur serveur (réessayez plus tard)

7. Bonnes pratiques

  • Ne jamais exposer votre clé dans du code frontend public.
  • Révoquer immédiatement une clé qui a fuité.
  • Utiliser une clé par projet/integration (traçabilité).
  • Respecter les rate limits (backoff exponentiel si 429).
